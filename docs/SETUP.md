# Google とつなぐための設定手順

> **2026年10月4日に設定済みです。** Google Cloud のプロジェクト `tegaki-calendar`（syfan0@gmail.com）に、
> 公開ステータス「本番環境」・クライアント「Tegaki Calendar Web」を作成し、クライアント ID を `js/config.js` に組み込みました。
> 以下は、作り直すときや別のアカウントで用意するときのための記録です。

手書きカレンダーが「あなたの Google カレンダー」と「Google ドライブ」を使えるようにするには、
Google のサイトで一度だけ **アプリの登録** をする必要があります。
これはご本人の Google アカウントでしかできない作業です。所要時間はおよそ 15 分です。

> この手順で作るのは、**このアプリ専用の「鍵の受け口」** です。
> お金はかかりません（クレジットカードの登録も不要です）。
> 手書きのデータは、あなたの iPad と、あなたの Google アカウントの間だけでやり取りされます。

最後に **「クライアント ID」**（`〜.apps.googleusercontent.com` で終わる長い文字列）が手に入ります。
それを Claude に渡してもらえれば、アプリに組み込みます。

---

## 1. プロジェクトを作る

1. Mac か iPad のブラウザで <https://console.cloud.google.com/> を開き、普段使っている Google アカウントでログインします。
   初めての場合は利用規約の画面が出るので、内容を確認して同意します。
2. 画面上部の「プロジェクトを選択」（またはプロジェクト名が表示されている部分）を押し、
   **「新しいプロジェクト」**（New project）を押します。
3. 次のように入力して **「作成」**（Create）を押します。
   - プロジェクト名：`tegaki-calendar`
   - 場所：「組織なし」（No organization）のまま
4. 作成が終わったら、画面上部のプロジェクト名が `tegaki-calendar` になっていることを確認します。

## 2. カレンダーとドライブの機能を有効にする

1. 次のページを開き、 **「有効にする」**（Enable）を押します。
   <https://console.cloud.google.com/apis/library/calendar-json.googleapis.com>
   （名前は「Google Calendar API」です）
2. 続けて次のページも開き、同じく **「有効にする」** を押します。
   <https://console.cloud.google.com/apis/library/drive.googleapis.com>
   （名前は「Google Drive API」です）

> 画面上部のプロジェクト名が `tegaki-calendar` になっていることを、毎回確かめてください。

## 3. アプリの名前と連絡先を登録する

1. <https://console.cloud.google.com/auth/overview> を開きます。
   「まだ構成されていません」と出たら **「開始」**（Get started）を押します。
2. 4 つのステップを順に入力します。
   | ステップ | 入力する内容 |
   | --- | --- |
   | アプリ情報 | アプリ名：`Tegaki Calendar`<br>ユーザー サポートメール：ご自分の Gmail を選ぶ |
   | 対象（Audience） | **「外部」**（External）を選ぶ |
   | 連絡先情報 | メールアドレス：ご自分の Gmail |
   | 完了 | 「Google API サービスのユーザーデータに関するポリシーに同意します」にチェック → 「続行」 → **「作成」** |

> アプリ名に「Google」や「Gmail」という言葉は使えません（Google の決まりです）。

## 4. 自分を利用者として登録し、「公開」にする

1. 左側のメニューの **「対象」**（Audience）を開きます。
2. 「テストユーザー」の **「ユーザーを追加」**（Add users）を押し、ご自分の Gmail アドレスを入れて **「保存」** を押します。
3. 同じ画面の上のほうにある **「アプリを公開」**（Publish app）を押し、確認画面で「確認」を押します。
   公開ステータスが「本番環境」（In production）になれば完了です。

> **なぜ「公開」するのか**：「テスト中」のままだと、7 日ごとに Google へのログインをやり直す必要があります。
> 「公開」しても、アドレスを知らない他人が使えるようになるわけではありません。
> Google の審査を受けていないので、ログインのときに **「このアプリは Google で確認されていません」**
> という画面が出ますが、ご自分で作ったアプリなので問題ありません（下の「初めてログインするとき」を参照）。

## 5. クライアント ID を作る

1. 左側のメニューの **「クライアント」**（Clients）を開き、 **「クライアントを作成」**（Create client）を押します。
2. 次のように入力します。
   - アプリケーションの種類：**「ウェブ アプリケーション」**（Web application）
   - 名前：`Tegaki Calendar Web`
   - **承認済みの JavaScript 生成元**（Authorized JavaScript origins）に、「URI を追加」で次の 2 つを入れる
     ```
     https://syfan0-star.github.io
     ```
     ```
     http://localhost:8000
     ```
   - **承認済みのリダイレクト URI**（Authorized redirect URIs）に、「URI を追加」で次の 2 つを入れる
     ```
     https://syfan0-star.github.io/tegaki-calendar/
     ```
     ```
     http://localhost:8000/
     ```
3. **「作成」** を押します。
4. 表示された **「クライアント ID」** をコピーします（`123456789-abcdefg.apps.googleusercontent.com` のような形です）。
   後から左メニューの「クライアント」の一覧でも確認できます。

> **注意（大事）**
> - 「生成元」の欄には、最後に `/` を付けない形で入れます。「リダイレクト URI」の欄には、最後の `/` まで正確に入れます。
> - 同じ画面に **「クライアント シークレット」** も表示されますが、これは **使いません。誰にも渡さないでください。**
>   クライアント ID のほうは、人に見られても問題ありません。

## 6. Claude にクライアント ID を渡す

コピーしたクライアント ID を、このチャットにそのまま貼り付けてください。アプリに組み込んで公開し直します。

> Google 側の設定が反映されるまで、**5 分から数時間** かかることがあります。
> 直後にログインして `redirect_uri_mismatch` などのエラーが出ても、しばらく待てば直ることがあります。

## 初めてログインするとき（iPad）

1. Safari で <https://syfan0-star.github.io/tegaki-calendar/> を開きます。
2. 共有ボタン（□に↑）→ **「ホーム画面に追加」** を押すと、アプリとして使えるようになります。
   以後はホーム画面のアイコンから開いてください。
   （Safari とホーム画面のアプリは中身が別扱いなので、ホーム画面から開いたら、もう一度ログインが必要です）
3. 「Google でログイン」を押します。
4. 「このアプリは Google で確認されていません」と出たら、 **「詳細」** → **「syfan0-star.github.io（安全ではないページ）に移動」** を押します。
   （開発者として syfan0@gmail.com ＝ご自分のアドレスが表示されていれば、このアプリです）
5. 許可を求める画面では、 **「すべて選択」にチェックを入れて** 「次へ」を押します。
   - カレンダーの予定の表示・編集：予定の表示と、手書きからの予定登録に使います
   - カレンダーの一覧の表示：どのカレンダーを表示するか選ぶのに使います
   - Google ドライブのアプリ専用データ：手書きの保存に使います（ドライブの他のファイルは見えません）

## うまくいかないとき

| 画面に出る言葉 | 原因と対処 |
| --- | --- |
| `redirect_uri_mismatch` | 手順 5 のリダイレクト URI が 1 文字でも違う（最後の `/` を含む）。設定直後なら数時間待つ |
| `access_denied`（「Google の確認手続きを完了していません」） | 手順 4 で自分をテストユーザーに追加していない／公開していない |
| `org_internal` | 手順 3 で「内部」を選んでいる → 「対象」で「外部に設定」 |
| `invalid_client` / `deleted_client` | クライアント ID の貼り間違い、または半年以上使わずに自動削除された |
| `disallowed_useragent` | LINE などのアプリ内ブラウザで開いている → Safari かホーム画面のアイコンから開く |
| 1 時間ほどで「Google に再接続」と出る | 安全のため、接続は 1 時間ごとに自動で更新されます。表示が出たら押してください（手書きは端末に保存済みなので消えません） |

## 大事：同じアドレスで別のサイトを公開しないでください

このアプリは `https://syfan0-star.github.io` というアドレス（「生成元」）で動いています。
GitHub Pages では、同じアカウントで公開したサイト（`https://syfan0-star.github.io/〇〇/`）は、
**すべて同じ生成元を共有します**。ブラウザから見ると同じ持ち主なので、

- Google へのログイン情報（ブラウザの localStorage に保存されています）と、
- **まだ Google ドライブに送っていない手書きを含む、端末内のすべての手書き**（IndexedDB）

を、ほかのサイトのページからも読んだり消したりできてしまいます。

そのため、このアプリを `syfan0-star.github.io` で使っている間は、**同じ GitHub アカウントで
ほかの GitHub Pages サイトを公開しないでください**（練習用のページなども含みます）。

どうしても別のサイトも公開したい場合は、このアプリ専用のアドレスに移す方法があります。

- 独自ドメイン（例：`calendar.example.jp`）を取得して、このアプリだけをそこで公開する
- このアプリ専用の GitHub アカウントを作り、そのユーザーサイト（`https://〈アカウント名〉.github.io/`）で公開する

移すときは、次の 3 つを **同時に** 変更する必要があります（Claude に頼めば作業します）。

1. `js/config.js` の `PAGES_ORIGIN_PATH`（アプリの正式なアドレス）
2. `manifest.webmanifest` の `scope` と、ホーム画面への追加のやり直し
3. 上の手順 5 の「承認済みの JavaScript 生成元」と「承認済みのリダイレクト URI」

> アドレスが変わると、ブラウザから見ると別のアプリになります。**古いアドレスの端末内にしか無い
> 手書き（まだ Google ドライブに送っていないもの）は、新しいアドレスには引き継がれません。**
> 移すかどうかは、毎日使い始める前に決めておくのがおすすめです。移す場合は、古いアドレスで
> 「保存済み」と表示されている（すべて送信済みの）ことを確かめてから切り替えてください。

## データの保存場所と削除方法

- 手書きは、Google ドライブの **「アプリ専用の非表示フォルダ」** に保存されます。ドライブの一覧には表示されません。
- 容量はご自分のドライブの容量から使われます（手書き 1 ページあたり数十 KB 程度です）。
- 全部消したいときは、Google ドライブ → 歯車 → 設定 → **「アプリの管理」** → 「Tegaki Calendar」の「オプション」
  → **「アプリの非表示データを削除」** で消せます（元に戻せません）。
- 予定は通常の Google カレンダーの予定として登録されます。消したいときは Google カレンダーからも削除できます。
